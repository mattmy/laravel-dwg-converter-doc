# 效能與安全

處理大型或不可信的 DWG 前，可依本頁規劃記憶體、磁碟空間與工作程序的資源上限。
請將上傳的 DWG 與產出的檔案都視為不可信資料。

## 在受控的工作程序中執行 {#在受控-worker-執行}

所有操作都是同步執行。處理較大檔案或使用者上傳內容時，建議透過佇列工作程序或容器執行，並明確
限制記憶體、CPU、程序數量、可寫空間與網路。應由應用程式控制同時執行的工作數，避免一次啟動過多轉換。

套件的逾時與大小限制有助於控制資源使用，但不能取代作業系統的沙箱隔離。

## 持續更新外部工具

使用仍在維護且包含安全修補的 LibreDWG、LibreOffice 與 ImageMagick 版本。簡短的 LibreDWG 版本字串
可能無法顯示已套用哪些修補，因此請保留安裝來源紀錄。也請檢查 ImageMagick 的安全政策，確認允許的
格式與外部工具符合部署需求。

## 記憶體與磁碟

- 命令執行前，來源會複製到套件專用的暫存工作目錄。
- `storeAs()` 會將完成結果串流至 Laravel Storage。
- `output()` 會將完整產物載入 PHP 記憶體。
- `toJson()->convert()` 和 `info()->read()` 會讀取並解碼完整 JSON，大小可能遠超過原始 DWG。
  `version()` 只讀檔頭。
- 圖片轉換會建立中介產物，最多執行三個轉換程序。
- 圖層查詢會將工具回傳的文字與 Collection 保存在記憶體中；`max_output_bytes` 不等於 PHP 記憶體用量的上限。

`onlyOn()` 可減少圖層回傳資料與 PHP 解析成本，但工具仍須完整解碼 DWG，不保證固定加速比例。

處理不可信來源時應保留正整數輸入／輸出上限。停用上限時，請為工作程序設定對應的記憶體與磁碟配額。

## 成功輸出代表的範圍

套件會確認命令執行完成，並檢查產物的基本格式結構，但成功不代表：

- 來源安全，或不會觸發解析工具的漏洞；
- 每個 DWG 物件都已正確解析或保留；
- 字型、xref 或其他外部資源都存在；
- DXF 在每個 CAD 應用顯示完全相同；
- 圖片與 AutoCAD 產物逐像素相同。

對外承諾相容性或效能前，請收集應用實際會遇到的圖檔，涵蓋不同 DWG 版本、語言、圖面物件與
後續使用的軟體，建立測試樣本。

## 日誌與隱私 {#logging-與隱私}

[暫存清理警告](./errors-and-troubleshooting#暫存清理警告)不含路徑、檔名、檔案內容、原始例外訊息或堆疊追蹤。

請避免在應用程式的日誌訊息中加入來源檔案內容、完整 JSON、使用者檔名或伺服器路徑。套件例外提供的
診斷資料雖已移除敏感資訊，完整例外紀錄仍可能透過原始例外或堆疊追蹤帶出路徑。請限制日誌存取權限，
並依自己的資料保留政策管理紀錄。

圖層、圖元與圖面資訊查詢的程序失敗診斷會省略原始 stderr。

## 圖元查詢 {#entity-queries}

圖元查詢仍會產生、讀取及解碼完整 JSON，再建立關聯索引與回傳資料。
`onlyLayers()` 只省下未選圖元的詳細解析，無法省去前面的完整 JSON 與索引成本。
三個檔案大小上限不套用於此查詢，請由部署環境限制工作程序的記憶體與磁碟用量。
`timeout` 與 PHP 原生 JSON 巢狀深度 `512` 仍適用；不會為了符合記憶體而截斷結果。
記憶體耗盡或程序被作業系統強制終止時，可能來不及拋出例外或清理暫存檔。

數值以 LibreDWG 輸出的 JSON 為準。已核對的 writer 使用 `%.14f`，例如 `1e-15` 可能先變成 `0`，
`1.000000000000001` 可能變成 `1`。套件不額外四捨五入，也無法偵測或還原這些上游精度損失。
這不影響合法零值的保留規則。
